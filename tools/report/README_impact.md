# 独立影响报告的构建与交付边界

报告面向仅持有 demo-v14 的读者。它另行提供，不修改冻结交付包。先在未添加
报告的干净 Git 克隆中运行完整 verify，再用另一份阅读副本，将 HTML
放入其 `docs/` 后，相对链接指向该包已有证据和指南章节。新增报告会使冻结
克隆出现未跟踪文件，不能继续把它当作干净交付克隆，不绕过该门。单文件也可
直接离线阅读，只有打开证据链接时才需要配套仓库。完整原始件本地留存，
可按请求提供，不链接未公开目录。

## 维护者重建（main）

```sh
python3 tools/report/build_impact_report.py
python3 tools/report/build_impact_report.py --check
python3 -m unittest tools.report.test_build_impact_report
```

生成器和本报告专属测试位于 main，不在 demo-v14 中。因此对客 HTML 不提供
这些文件的链接，也不要求读者执行冻结包中不存在的命令。main 的完整
`reproduce.sh verify` 通过既有报告测试模块发现这些测试；入口字节不变。

## 三个构建硬门

- 数字：`impact_sources.json` 固定公开输入字节哈希；按行重算已有统计并
  对照已发布精确值，不改任何测量数据或统计定义。
- 链接：`impact_delivery.json` 固定 demo-v14 的完整提交 SHA；从 Git 对象
  树读取文件及 Markdown/HTML 锚点，逐条核验报告链接，并核验所用证据与
  交付快照的字节一致。当前工作区存在但交付快照不存在的文件或锚点仍失败。
  不依赖 tag 名解析。缺少对象时明确失败并提示
  `git fetch --no-tags origin 7289a47b9d24791944cd3b02c00f24b8cb76aa3b`，不降级跳过。
- 用词：检查生成的完整 HTML（含图注、属性、meta、注释）及拼接后的文本；
  禁止相关署名和过程用语。实体、大小写、全角与零宽字符均纳入检查。
  回归测试覆盖正文以外的命中，以及构建阶段确实拒绝输出。
