### vk_send 预演

`vk_send` 在本镜像上生效时返回码仍为 1。生效性由 AUL 生命周期确认：

```text
CURRENT  00:18:16  PAUSED / STATUS_BG
SEND73   VK_RC=1
00:18:19 RESUMED / STATUS_FOCUS
SEND182  VK_RC=1
00:18:25 RESUMED / STATUS_BG
```

即 `73` 将频道列表带到前台，`182` 将其送回后台。预演通过后才启动正式采集。

## 8. PID 记录、失败与限制

- 10 个目标从 sample 0 到 374 均保持原 PID；无 PID 变化、无 `NA`。
- `AppProcA` 在 S1 不运行，指定目标缺失。
- `vk_send 73/182` 的前后台变化经 AUL 实证；`116/96/95/138` 无逐键画面
  或 dlog 证据，只能确认命令按序调用。没有键因“已证实无效”而被剔除。
- 六轮目标 key offset 完全相同，但 `vk_send` 为阻塞命令，实际 lateness
  最大 2131.862 ms；节奏不是毫秒级完全一致。
- 采样有 154 次 deadline overrun，最大相邻间隔 7.576596 s；所有目标点均在，
  但短峰值可能落在较疏的区间之间。
- `ServiceA`、`ServiceB` 的非单调波动不能按三种合同形态强行分类。
- 平台高度是 glibc arena Private Dirty 代理的上界估计，不是
  `malloc_info` 空闲字节，也没有在产品板调用 `malloc_trim` 验证。
