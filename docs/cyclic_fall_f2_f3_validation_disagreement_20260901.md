## 3. F3：定义审计与逐轮复算

已发表分析器的原定义为：

1. `fall_start`：peak 后第一个低于 90% excursion 阈值的样本（`analyze_cyclic.py:115–118`）；
2. `valley`：`fall_start` 起至轮窗末尾的最小 PD 样本（`:119`）；
3. `fall_edge`：`valley.elapsed - fall_start.elapsed`（`:128`）；
4. `peak_band`：`fall_start.elapsed - high_entry.elapsed`（`:127`）。

这确认 `fall_edge` 会把“释放已经发生后的谷底最小值等待时间”计入下降沿。逐轮复算如下：

| 轮次 | peak / fall_start / valley (kB) | fall_start 前已释放 | 原定义 fall_edge (s) | 首次观测入带延迟上界 (s) |
|---|---:|---:|---:|---:|
| R1 | 13272 / 3512 / 3476 | 99.632503% | 18.615723 | 5.429566 |
| R2 | 10068 / 3844 / 3824 | 99.679693% | 19.662990 | 6.077082 |
| R3 | 12612 / 4564 / 3992 | 93.364269% | 5.744246 | 8.590703 |
| R4 | 10708 / 6772 / 4032 | 58.957460% | **24.460553** | 8.698081 |
| R5 | 8176 / 6248 / 4144 | 47.817460% | 4.166497 | 8.497841 |
| R6 | 10392 / 8372 / 4212 | 32.686084% | 19.703490 | 7.861624 |
| R7 | 8396 / 4128 / 4064 | 98.522622% | 20.949599 | 5.223693 |
| R8 | 10044 / 6820 / 4252 | 55.662983% | 22.639416 | 8.910626 |

末列定义为观测 peak 到第一次采样进入 `PD <= valley + 5% × (peak - valley)` 的延迟。八轮范围为 `5.223693–8.910626 s`，中位数 `8.179733 s`。它是离散采样下的完成时间上界，不是精确的真实塌落持续时间；例如 R2 的 `6.077082 s` 正好跨越 peak 与下一样本之间的采样空档，实际跨带时刻只能定位在空档内。

F3 的主要机理结论得到支持：R2 例子确为 `3844 -> 3824 kB`，在 `fall_start` 前已完成 `99.679693%` 的释放；原 `fall_edge` 不是实际塌落时长。首次观测进入谷底 5% 带发生在峰后约 `5.22–8.91 s`，但采样空档不允许把该值升级为精确机制时长。分歧只在 PM 给出的完整八轮范围上限，但停止门要求仍必须暂停后续修订。

完整逐轮证据见 [`serviceA_fall_recheck.tsv`](../data/raw/cyclic_fall_attribution_20260901/serviceA_fall_recheck.tsv)，输入哈希、分析器哈希和摘要见 [`summary.json`](../data/raw/cyclic_fall_attribution_20260901/summary.json)。
