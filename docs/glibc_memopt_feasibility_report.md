### Build and packaging flags relevant to memory/flash

- Tizen spec forces libc build flags to `-O2 -g -U_FORTIFY_SOURCE`, removes fortify/stack-protector/LTO-related flags, removes Thumb flags, and adds `-funwind-tables -fPIC` (`packaging/glibc.spec:329-356`).
- Configure options include `--enable-profile`, `--enable-bind-now`, `--disable-nscd`, `--disable-experimental-malloc`, `libc_cv_cc_pie_default=yes`, `--enable-stackguard-randomization`, `--disable-multi-arch` on non-x86, `--enable-static-pie`, and Tizen `--enable-dlconf`/`--enable-dlconf-all-dirs` (`packaging/glibc.spec:371-402`).
- `glibc_post_upgrade` alone is compiled with `-Os`; libc itself is not (`packaging/glibc.spec:409-416`).
- Full locale generation is disabled by default: `build_locales 0` (`packaging/glibc.spec:59-76`). The base package still always installs minimal `en_US.UTF-8` with `--no-archive` (`packaging/glibc.spec:547-556`, `packaging/glibc.spec:796-800`).
- Timezone data is removed from this package and expected from a standalone package (`packaging/glibc.spec:629-633`).
- All gconv modules are built/installed by the glibc build system (`iconvdata/Makefile:26-65`, `iconvdata/Makefile:133-147`, `iconvdata/Makefile:252-259`) and packaged under `glibc-locale` (`packaging/glibc.spec:813-823`).
- Runtime glibc package includes NSS modules including `libnss_compat`, `libnss_db`, `libnss_dns`, `libnss_files`, `libnss_optfiles`, `libnss_hesiod`, plus `libc_malloc_debug.so.0` (`packaging/glibc.spec:752-771`).
- Shared libraries intentionally keep `.symtab`/`.strtab` via `STRIP_KEEP_SYMTAB=*.so*` for debugging tools (`packaging/glibc.spec:529-538`).

### GLIBC_TUNABLES availability

- This tree does not use a visible `--enable-tunables` configure flag in `packaging/glibc.spec`; tunables are generated and built into this version by the common build (`Makeconfig:1257-1269`) and `dl-tunables` is included in dynamic-loader routines (`elf/Makefile:78-85`).
- Runtime initialization calls `__tunables_init` for dynamically linked processes (`sysdeps/unix/sysv/linux/dl-sysdep.c:104-112`) and for libc startup (`csu/libc-start.c:264-268`).
- Parser recognizes `GLIBC_TUNABLES` and environment aliases, but ignores tunables for `AT_SECURE` programs (`elf/dl-tunables.c:289-355`).
- Tunable callbacks are invoked only when the tunable was initialized from the environment (`elf/dl-tunables.c:437-469`, `elf/dl-tunables.h:108-115`).

## Open Questions / Cannot-Verify List

- On-device RSS/PSS deltas for target Tizen TV services under each tunable. Source can prove feasibility, not savings magnitude.
- Allocation-heavy benchmark results on armv7l and aarch64 for `arena_max`, `tcache_count`, `tcache_max`, `mxfast`, and fixed mmap/trim thresholds. These decide whether each candidate stays within the 5-10% budget.
- Final service launch environment and whether each target process is `AT_SECURE`; `GLIBC_TUNABLES` is ignored in secure mode (`elf/dl-tunables.c:299-301`).
- Tizen TV kernel THP/hugetlb state and measured huge-page RSS impact. Source shows tunables, not whether the target kernel makes them relevant.
- Actual final runtime image package set: whether `glibc-locale`, `glibc-i18ndata`, `glibc-devel-static`, `glibc-profile`, or debug utilities are installed on TV images.
- Product encoding allowlist for gconv pruning: subtitle/media/web/regional requirements need validation outside this repo.
- Product NSS requirements and final `/etc/nsswitch.conf`; source default uses `compat`, `optfiles`, `securitymanager`, `files`, `dns`, and `nis`, but device images may override it.
- Whether production tooling requires `.symtab`/`.strtab` in shared libraries; the spec explicitly says valgrind/PurifyPlus/libthread_db currently rely on them.
- Whether dlconf is required by product security/isolation policy; source proves it is enabled and memory-relevant, not whether it is optional for TV.

## negative_facts

- This audited Tizen tree is glibc `2.40`, not a newer upstream version (`version.h:1-4`, `packaging/glibc.spec:87-88`).
- No current Tizen patch changes arena default formula, tcache default, stack-cache default, malloc tunable list, or nptl stack-cache logic versus the checked `upstream/2.40` comparison.
- The current Tizen malloc source patch is a memalign overflow/CVE guard, not a memory policy change (`malloc/malloc.c:5036-5053`, commit `93fd24e807`).
- Tcache is compiled in and enabled by default in this audited tree (`malloc/malloc.c:292-317`, `malloc/malloc.c:1888-1930`, `malloc/malloc.c:3102-3288`). Historical `disabled tcache for memory test` commits are not ancestors of HEAD.
- `GLIBC_TUNABLES` parsing is present and functional in the source, but ignored for `AT_SECURE` programs (`elf/dl-tunables.c:289-355`).
- There is no `--enable-tunables` spec/configure flag to toggle here; tunables are generated and built by the common build (`Makeconfig:1257-1269`, `elf/Makefile:78-85`).
- The base package already avoids a locale archive; it installs minimal `en_US.UTF-8` using `--no-archive` (`packaging/glibc.spec:547-556`, `packaging/glibc.spec:796-800`).
- `nscd` is disabled in the Tizen glibc configure options (`packaging/glibc.spec:371-376`), and `nscd/Makefile` only builds/install nscd when enabled (`nscd/Makefile:25-47`).
- `malloc_trim` in this tree is not top-only; it can `MADV_DONTNEED` interior page-aligned free chunks (`malloc/malloc.c:5151-5195`).
- `glibc.malloc.arena_test` is not an arena cap; `arena_max` is the direct cap (`malloc/arena.c:830-852`).
- `glibc.malloc.top_pad=0` is not a new saving in this tree because `mp_.top_pad` already initializes to 0 (`malloc/malloc.c:934-938`, `malloc/malloc.c:1915-1918`).
- `glibc.pthread.rseq=0` cannot remove the embedded 32-byte rseq area from `struct pthread` (`nptl/descr.h:407-419`).
- `glibc.malloc.check`/`MALLOC_CHECK_` are not active in normal libc by themselves in this tree; debug behavior lives in `libc_malloc_debug` and tests preload it (`malloc/malloc-debug.c:49-78`, `malloc/Makefile:330-335`).
- `malloc_perturb` is default-off (`malloc/malloc.c:1978-1994`).
- No source build artifacts, package size outputs, or on-device PSS samples were present in the repo; numeric savings above are source-derived order-of-magnitude estimates, not measurements.
