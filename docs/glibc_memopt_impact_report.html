TIZEN · GLIBC · 运行时内存回收

让已释放的内存，真正回到系统

本方案不替换 libc、不改本次对照实验的二进制；在现有 glibc 上按释放相位调用 malloc_trim(0)，让可归还的空闲页退出进程驻留内存。

内存有明确收益；按固定 p99 判据未检出性能劣化，已测窗口未发现 OOM/LMK 或目标重启。 这是带范围的“未检出副作用”，不是所有性能指标零影响或长期稳定性的证明；本报告不宣称性能提升。

只组织既有公开证据，没有新测量。收益指进程内存回收，不等于整机或产品收益。

集成影响与选择性启用

本次 trim/none 对照使用相同 ELF，由运行时参数选择是否调用，不替换 libc，不因启用开关改变二进制体积或构建产物。 启动时间未做专项测量；释放点设计不要求在启动路径执行 trim，但“产物未变”不是启动耗时完全不变的实证。产品增加调用点是否需要 owner 改动，由集成方式决定。composition.json · L1 复算同产物对照口径

不满足门的目标可以完全不调用，因此没有新增的 trim 调用开销；这是一种收缩影响面的方式，不是整个系统风险为零的保证。

产品启用：连续通过四道硬门

反信号排除 → 堆内驻留确认 → 实测 trim 探针收益达标 → 代价预算

  1. 已经自动归还的周期分量排除；PD 自发下降不是需要 trim 的证据。
  2. 以 malloc_info 的 M7 口径确认 glibc bins 中有空闲驻留，不把 smaps 平台直接当作可回收量。
  3. 同目标、同释放相位实测 trim；收益须达到事前固定阈值，不能由估算器预测替代。
  4. 调用时间、下一周期 faults 与活跃并发锁停顿都须符合业务预算；未过门则不启用。

边界与未决

  • 测试板量级，不等于产品收益。进程 RSS 回收明确；系统净效应未检出，不外推整机收益或业务收益。
  • 产品候选尚未完成 floor 复确认与 live/bin 分解。需要目标 owner 配合采集堆内分布；现有平台高度只能登记候选。
  • 真实并发预算仍有缺口。合成代理不能覆盖产品并发；gst 在 NULL 后调用，只补了该释放点与后续循环代价，未直接量化活跃分配时全 arena 锁停顿、帧时延和能耗。
  • 镜像、内存环境与负载差异。测试板的对象尺寸、分配历史和释放方式不能替代产品现场，产品必须重新验证启用门。
  • 不作统一启用承诺。已测常驻守护收益很小，M7 驻留与估算器都不能给出统一收益阈值；未检出 p99 劣化不等于所有性能维度无变化。
