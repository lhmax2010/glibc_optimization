TIZEN · GLIBC · 运行时内存回收

让已释放的内存，真正回到系统

本方案在业务批量释放对象后，按条件调用 glibc 的 malloc_trim(0)，把仍留在堆内的可回收空闲页归还系统，降低进程内存占用。

malloc_trim 是 glibc 提供的运行时接口：它尝试把分配器中已经空闲、但仍占用物理内存的完整页归还内核。 操作系统按页回收内存；一页内只要还有必须保留的数据，就不能整页丢弃。因此，free 释放的对象字节不一定都能立即转化为可回收页。

进程内存有明确收益；耗时最长的那部分操作，加上本方案后的变化仍落在不加本方案时重复测量的波动范围内。 这表示没有观察到这部分操作的额外变慢，不等于所有性能指标零影响；通常耗时水平仍有小幅变化，后文如实列出。本报告不宣称性能提升，也不把有限测试当作长期稳定性的证明。

只组织既有公开证据，没有新测量。收益指进程内存回收，不等于整机或产品收益。

摘要内存收益性能与稳定性适用面边界

一页摘要

本报告包含两种批量分配—释放负载：混合尺寸分配负载反复申请不同大小的对象，再集中释放其中一部分；中等尺寸为主的分配负载执行同样的过程，但以中等大小对象为主。 媒体解码循环负载则反复进行软件解码，停止管线并释放资源后再进入下一轮。 常驻 UI 合成器进程（enlightenment）作为不同使用场景的对照：它持续负责界面合成，不以大批对象集中释放为主要形态。

下文的不调用对照指使用相同二进制和相同负载参数、但不调用 trim 的一组运行；与调用 trim 的运行在对应时点取样。 RSS是进程当前驻留在物理内存中的总页量，包含代码、栈、共享页及其他映射；堆内 Private_Dirty（简称堆 PD）仅统计本报告归类到 glibc 堆的私有脏页，二者不是同一个范围。 所有内存图表使用 MiB 或 KiB。

为了不让偶然的一次结果代表全部测试，下文的“代表值”取重复结果排好顺序后居中的数；若正好有两个居中数，则取二者正中间的值。“波动幅度”是同一条件重复运行时，最大结果与最小结果相差多少。

耗时最长的那部分操作变化未超出波动增加约 6.229 ms，小于不调用时的重复波动 6.784 ms；不等于所有操作毫无影响。

适用：由 glibc 管理、批量释放后仍有驻留空闲页、实测收益达标且代价在预算内的目标。 不适用：已经自行归还的那部分内存，以及没有可回收驻留空闲页、使用其他分配器或实测收益不足的进程。 同一进程中其他尚未归还的内存仍须单独实测；常驻服务不能因“有空闲块”就默认启用。

性能结论的必要限定：同一媒体解码数据中，通常耗时水平增加 +1.870462 ms，超过不调用时自身的重复波动 0.173927 ms。这项小幅变慢可以观察到，不能概括成“全部业务延迟无变化”。

性能与稳定性：检查负面影响，不宣称提升

释放点调用是有代价的；耗时最长的操作变化没有超出不调用时的波动，并不等于所有指标零影响。通常耗时的小幅变化、重新使用内存时的缺页成本，以及尚未验证的并发影响都需要保留。

业务延迟：较慢操作的变化未超出波动，通常耗时仍有小幅变化

我们在每次运行中选出耗时最长的一轮，再比较调用与不调用两种情况。 加上本方案后增加 +6.228611 ms，小于不调用时重复运行的波动 6.784167 ms，因此没有观察到这部分较慢操作的额外变慢。

数值说明：两者还相差 0.555556 ms（约 0.556 ms）；已测增加量相当于上述波动幅度的 91.8%。每种情况重复三次，每次观察第 2–51 周期的 50 轮；每次先取最慢一轮，再用三次结果的代表值比较。

没有观察到下降不等于所有指标零影响，也不能证明产品业务的服务质量完全不变。 同一批数据中，先从每次运行里选出通常耗时水平，再比较重复结果的代表值，增加了 +1.870462 ms；这高于不调用时自身的波动 0.173927 ms，属于可观察到的小幅变慢。 这里的通常耗时水平，是将每次的 50 轮从快到慢排列，选居中的两轮里较快的一轮。尚不能证明任意活跃并发线程的锁停顿无影响。

缺页与稳定性：看清窗口与异常记录

minor fault 指无需从后备存储读入页面就能处理的缺页；major fault 则需要调入页面。前者增加通常表现为页映射重新建立的成本，不能与后者混为一谈。 OOM/LMK 指内存不足或低内存杀进程记录；zram 是内存中的压缩交换设备，本报告记录其原始数据量、压缩数据量与占用内存量的变化。

  • major fault：系统前后对照的采样时段均为 0；有定义的下一周期也为 0，末周期的缺失值不计作零。批量分配负载下一周期与媒体解码第 2–51 周期同样为 0。
  • 冷启动例外：媒体解码不调用 trim 的首重复、首周期，在任何 trim 前出现 4 次 major fault，外部序列同样记录 4；不归因于 trim，但不能写“全部实验全程为零”。早期媒体实验的附加采样字段缺失不冒充零，以有效目标内及外部序列为准。
  • 再激活成本：混合尺寸与中等尺寸为主的分配负载，下一周期分别增加 +1351 / +1465 次 minor fault；媒体解码则先比较两组每次运行的缺页总数代表值，再摊到每循环，约增加 +359。它与空闲页丢弃后重新建立映射相容；minor fault 本身不需要磁盘页读入，不能据此承诺整个进程没有其他磁盘 I/O。
  • 已测稳定性：批量分配与媒体解码的记录时段零 OOM/LMK，zram 三项变化均为 0；媒体目标正常退出，常驻 UI 合成器的已完成观测中进程号和启动身份保持，未发现崩溃或重启。不将有限实验窗口改称长期无异常证明。
  • 并非全历史零告警：大块释放后的回收基准有已知告警豁免记录；触发理由与出现时段可复现，未做无害性根因证明。系统前后对照实验分期执行、延期完成收尾，已知非空目录保留，不能表述成不中断运行且现场零残留。

集成影响与选择性启用

本次调用与不调用的对照使用相同可执行文件，由运行时参数选择是否调用，不替换 libc，不因启用开关改变二进制体积或构建产物。 启动时间未做专项测量；释放点设计不要求在启动路径执行 trim，但“产物未变”不是启动耗时完全不变的实证。产品增加调用点是否需要目标维护者改动，由集成方式决定。

不满足门的目标可以完全不调用，因此没有新增的 trim 调用开销；这是一种收缩影响面的方式，不是整个系统风险为零的保证。

适用面：批量释放收益明显，已测常驻服务收益很小

常驻 UI 合成器的初始观测、应用释放后的观测，实测回收分别为 272 KiB / 36 KiB；后续三次观测为 88 / 0 / 4 KiB。 后续 RSS 的代表降幅为 0.003906 MiB / 0.033659%，小于重复测量自身的波动 0.089844 MiB，无法判定为真实变化。其注入耗时代表值 1899.209517 ms 包含 gdb 调试器附加、通过 ptrace 控制目标进程等注入开销，不与释放点约 1 ms 的调用数字混列。

空闲块驻留量不等于可回收量。glibc 归还受完整空闲页与分配器状态约束，碎片化可能让许多空闲字节无法形成可归还页；这些聚合观测不能唯一定位块地址或机制路径。 整页估算器给出的预计回收范围，在严格配对的 15/15 个观测中都没有覆盖实测值，因此不能用空闲块大小分布的预测替代实际试调用。

产品启用：连续通过四道硬门

排除已经自行归还的那部分内存 → 确认释放后的空闲内存仍留在堆内 → 实测 trim 回收收益达标 → 确认代价在预算内

  1. 对已经自行归还的周期分量，不启用额外回收；堆 PD 自发下降不是需要 trim 的证据。
  2. 用 glibc 的 malloc_info 接口查看各分配区域的空闲块信息，确认有已释放但仍驻留的内存；不能只看到内核 smaps 的内存曲线不下降，就认定这些内存全都可回收。
  3. 在同目标、同释放时点试调用 trim 并测量实际收益；收益须达到事前固定阈值，不能用空闲块尺寸直方图的预测替代。
  4. 调用时间、下一周期缺页与活跃并发锁停顿都须符合业务预算；未过门则不启用。

边界与未决

  • 测试板量级，不等于产品收益。进程 RSS 回收明确；系统可用内存的变化没有超出测量自身的波动，不能据此宣称整机收益或业务收益。
  • 产品候选的持续内存占用尚未重新确认，也未区分仍在使用的对象与已释放的空闲块。需要目标维护者配合采集堆内分布；曲线上不再下降的内存量只能用来登记待查对象。
  • 真实并发预算仍有缺口。合成负载不能覆盖产品并发；媒体实验在管线停止释放后调用，只补了该释放点与后续循环代价，未直接量化活跃分配时各分配区域锁竞争造成的停顿、帧时延和能耗。
  • 镜像、内存环境与负载差异。测试板的对象尺寸、分配历史和释放方式不能替代产品现场，产品必须重新验证启用门。
  • 不作统一启用承诺。已测常驻守护收益很小，空闲块驻留量与整页估算器都不能给出统一收益阈值；没有观察到较慢操作额外变慢，不等于所有性能维度无变化。
